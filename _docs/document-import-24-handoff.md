# Issue #24: local document import handoff

## Updated decisions after QA at f88ff4c

The human approved `pdfjs-dist` 6.4.299; prior dependency-approval language below is historical. Run it locally without document network transfer. Support valid incremental, cross-reference-stream and PDF 2.0 examples, test specific corrupt fixtures, and describe parser recovery and unsupported cases honestly; no parser establishes universal corruption detection.

The current-context check below means checking before initially displaying newly loaded records and before modifying them, not a guarantee that an already displayed row disappears at the instant an independently controlled backend switches datasets. Any check can be followed immediately by a switch. Fail closed on a changed or unavailable context, clear displayed rows and invalidate pending work when detected, hide and revalidate on focus, visibility or page resume, and fence asynchronous responses with a context generation. Visible-page polling is best effort, not a hard time bound: suspended or throttled pages and connectivity may delay detection. IndexedDB namespace keys prevent mixing, but the localhost endpoint is unauthenticated and does not provide privacy against another local client. A coordinated revocable session would require a separate design and could not retract already viewed information.

## Goal

Validate and retain a student-selected PDF or DOCX on the dashboard's local browser, associated with a chosen course. The existing backend mock import is not evidence that a document was read or extracted. Extraction remains #25/#26/#27.

## Acceptance criteria and implementation decisions

1. The syllabus page shows the selected course, source (local selection, optionally associated suggestion), name, size, SHA-256 identity and a local import state. The 20 MiB initial limit is a single configurable application setting, shown before file selection; check size before reading. Explicit selection is mandatory. A suggestion only preselects its course and prompts for a local file; no suggestion or arbitrary URL is fetched.
2. Define the contract before implementation: `File`/`Blob` never enters the HTTP adapter, extension messages, FastAPI, SQLite, logs, or AI. Store bytes and local metadata together in dashboard-origin IndexedDB; the extension's separate origin cannot directly access this store. No backend metadata write is required for this local import. Amend root `openapi.yaml` first to describe the existing `/api/documents/import` accurately as a legacy filename/digest mock with simulated results, and explicitly state that this local workflow does not call it. Preserve existing endpoint, schema and mock behavior, including #22's digest/semantic tests; do not create fabricated extraction candidates. A later coordinated handoff for extraction is owned by #25/#26, not implied here.
3. Key content by SHA-256 and association by trusted startup dataset identity plus course ID and digest, in an atomic IndexedDB transaction. Same content in the same course is a duplicate even if renamed; a different course requires the student to explicitly confirm adding that association, retaining the original. Store one blob with separate course associations within the same dataset, never sharing across datasets. Concurrent attempts must not create duplicates.
4. Reject oversized files with the displayed limit, `.doc` with a legacy-format explanation, native Google Docs links/files with instructions to export PDF/DOCX, and mismatched extensions/signatures with a specific message. Verify PDF header, structural trailer and cross-reference/root consistency, and DOCX ZIP central directory, entry bounds, CRC and required `[Content_Types].xml` and `word/document.xml`; reject truncation, invalid offsets, encrypted/unsupported entries and corrupt containers. Enforce bounds before decompression and protect against decompression bombs. Browser-native APIs only; if robust supported-format validation cannot be achieved without a new dependency, stop and request dependency approval rather than claim success on magic bytes alone. No external validation service.
5. Display queued, parsing (local validation and hashing, not extraction), complete (validated and stored locally, extraction not performed), failed with actionable reason and retry, and cancelled. Cancellation aborts work or discards its result before commit; retry requires the retained selected file or explicit reselection. A restart recovers completed associations; unfinished work is marked interrupted/failed with retry, never silently complete. Handle storage quota and unavailable crypto/IndexedDB as failures without partial association or phantom success.
6. A network capture during selection, validation, duplicate and retry shows no document content transfer, no automatic Moodle request and no upload. Moodle credentials/cookies/tokens never enter the dashboard, backend, storage records or logs. The current suggested-file handoff has no live retrieval or verified session signal; a deterministic test fixture may exercise sign-in guidance on an explicit session-expired signal, but must be labeled simulated. Genuine session-loss acceptance remains blocked until the separately authorized live collector/session integration exists (#3/#9); do not claim this criterion passes from a fixture.

## Identity and lifecycle decision

IndexedDB is scoped by browser profile and dashboard origin, not backend process or extension origin. The backend startup namespace is trusted and immutable, but is not currently exposed to the dashboard. Add a narrow `GET /api/local-context` to source `openapi.yaml` before implementation, returning only `{ "datasetId": "<opaque random UUID>" }`; it takes no namespace, identity, URL or other selector. A migration adds a unique opaque random ID per existing and new namespace in SQLite, generated once under the existing initialization transaction; retry and concurrent initialization must return the same committed ID. IDs are not derived from identity, do not reveal user or origin, persist across process restarts, reset and SQLite backups, and differ across namespaces. A new database gets new IDs. An injected in-memory store generates an ephemeral ID once per store instance. A restored SQLite backup preserves its IDs but does not restore browser files: document that browser storage needs separate backup/reselection and clearing it or changing browser origin/profile loses access. Do not leak raw namespace, Moodle username, credentials or file content. Failure to obtain context fails closed; never substitute a global ID. The endpoint has the existing localhost-only trust boundary and is not authentication.

The permitted coordinated adapter and OpenAPI change is necessary to make #24's local-only handoff safe; the associated minimal backend migration/read route is the direct implementation of that contract, with no document-byte transfer. Verify migrations, rollback, unique IDs, concurrent creation, restart, reset, backup, memory lifetime, malformed requests and storage failures. Same-origin proxy uses this binding; extension storage remains separate. Different dashboard origins cannot see each other's files. Capture the dataset ID at start, re-fetch just before a commit, and reject a changed/unavailable context. Because a backend restart can race the check, associate only under the captured ID and always re-fetch current context before displaying or modifying records; never merge namespaces. Do not promise this unauthenticated API protects data against another local client.

Use exact stable `Course.id` values from the current Snapshot (not course code, display title or Moodle URL). Require an existing explicitly selected course; a suggestion may preselect its own existing course but selecting a local file remains an explicit student action. Store blobs by `[datasetId, digest]` and associations by `[datasetId, courseId, digest]` with unique IndexedDB keys. In one read-write transaction recheck the keys, add blob if absent, and add association only after explicit cross-course confirmation; use transaction serialization and uniqueness to handle competing tabs. Same-course duplicate returns existing association without modifying it. The confirmation identifies the already-associated course(s) and target course, and a declined or cancelled confirmation makes no change. Retain selected filename/source/size per association, never infer course from a filename. Quota or transaction failure aborts all writes. Context changes invalidate pending confirmations.

## Validator feasibility and dependency decision

The checked `pyproject.toml` directly declares FastAPI, SQLAlchemy and Uvicorn, and `frontend/package.json` has no PDF or ZIP parser direct dependency. Backend Python ZIP facilities would require sending file bytes across the HTTP boundary, which is not authorized. Browser Web Crypto supplies SHA-256 and IndexedDB retains Blob locally; browser decompression support can help ZIP deflate but does not supply a PDF parser or ZIP directory, integrity and OOXML validation. Transitive packages are not approved direct dependencies or a stable application interface. The repo provides no evidence that a complete, robust PDF validator is already available to the browser. Do not pretend PDF header/trailer checks constitute full corruption detection.

Engineering may implement bounded ZIP/OOXML structural checks with browser primitives, but real PDF cross-reference, object streams, incremental updates, encryption and malformed inputs need a mature locally executed parser. The best candidate for a focused approval request is `pdfjs-dist` as a direct frontend dependency, with version and lockfile chosen only after compatibility/security review; it must run locally with network fetching, external fonts and scripts disabled and no document data transmitted. It can parse PDF structure, but recovery-oriented parsing is not a guarantee that all corruption is detected: engineer must define supported PDF variants and reject parser errors/repair indications honestly, with fixtures. DOCX remains bounded ZIP checks including CRC, required parts and XML validity; if browser primitives cannot implement those safely, separately request a maintained browser ZIP library after evaluating its integrity and bounded-decompression behavior. Neither package is approved or installed by this handoff. If reliable checks cannot be implemented without approval, continue other independent work and report this dependency as a blocker; do not lower the original acceptance criterion.
